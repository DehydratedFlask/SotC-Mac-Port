## Tool selection and native build

REA `open_binary` rejects this PS4 PKG format as unsupported. Ghidra is used after extraction,
not claimed to extract the package. User-suggested
[ShadPS4Plus releases](https://github.com/AzaharPlus/shadPS4Plus/releases/tag/PKG_EXTRACTOR_1_1)
provide Windows/Linux binaries. The same pinned source was built for macOS ARM64.

- Source: `reference/shadPS4Plus-pkg`, commit `771a8d58aff540448c7cbace7c40a66a5daf010d`.
- Build adapter: `tools/pkg-extractor/CMakeLists.txt`; upstream source is unchanged.
- New dependency: Crypto++ 8.9.0. SDK zlib and CoreFoundation reused; see INSTALL_LOG.
- First build failed on Linux spelling `fseeko64`. Adapter uses Darwin's 64-bit `fseeko`.
- Second build passed. `file local/build/pkg-extractor/pkg_extractor` reports Mach-O ARM64.
- No submodule was initialized or prebuilt x86/Linux executable used.

Already-executed commands, each from the workspace root:


## Repeatable extraction

Do not re-extract over an existing tree blindly. Preserve it or choose a new output directory,
then compare identities. The upstream extractor always appends the title ID; updates append
`-patch`, and DLC gets a content-label subfolder. Supply an explicit output argument to avoid
its interactive prompt/default extraction alongside the original PKG.

Executed base/update commands:

```sh
local/build/pkg-extractor/pkg_extractor "Shadow of the Colossus/Update v1.01/Update v1.01.pkg" local/extracted
local/build/pkg-extractor/pkg_extractor "Shadow of the Colossus/Shadow of the Colossus.pkg" local/extracted
```

Outputs: `local/extracted/CUSA08809/` and `local/extracted/CUSA08809-patch/`.
Four DLCs were extracted with the same tool and output parent `local/extracted/addcont`.
Logs: `logs/extract-base.log`, `logs/extract-update.log`, `logs/extract-<DLC-name>.log`.
Base PFS extraction reported 37/37 files; update 14/14, in addition to package metadata entries.
Extracted-file totals in the manifest include metadata and therefore differ from these PFS counts.

Important CLI behavior: `--check-type` returns 101 for base, 102 for patch and 103 for DLC.
These are classification results, not failures. Conversely, ordinary extraction can print
an error and return zero. Validate logs and actual outputs rather than trusting exit zero alone.

Never case-blind merge `cachedFiles.psarc` (base) and `cachedfiles.psarc` (update). DATA-02 must
determine lookup/case and archive-member override semantics from engine readers; keep both
physical versions and record an explicit logical overlay. Do not flatten DLC into the base.

## SELF to ELF: observed plaintext reconstruction

The extracted eboot starts with SELF magic `4f153d1d`. The pinned SoTC helper
`scripts/prepare.py:40-85` admits plaintext segments, rejects encrypted/compressed segments,
and checks required-segment availability. The local wrapper reuses it without executing game code.

Executed:

```sh
python3 scripts/unwrap_self.py local/extracted/CUSA08809/eboot.bin local/re/eboot.elf
file local/re/eboot.elf
```

| Artifact | Bytes | SHA256 |
|---|---:|---|
| Extracted eboot.bin | 65,314,052 | `21982727c6f97fd415b3af5e99c5e071619c4dcc2248787a701a31a45ab0a4e0` |
| Reconstructed eboot.elf | 65,214,308 | `d0723afbdbd4cb3775c683a2b7f09534d371ce6d0b18146fc35b4d50c25861d3` |

ELF64 little-endian, machine 62/x86-64, type `0xfe10`, entry RVA `0xf120`, 11 program headers.
The reader reports missing program-header segment 10: type `0x6fffff01`, file size 2,928,
memory size zero. Its semantic importance is UNCLASSIFIED. It is not one of the reader's
required executable/dynamic/relocation segments. Do not call this an entirely lossless SELF
conversion or silently ignore the missing record in a later reconstruction.

Full segment map: `local/re/eboot.identity.json`; reconstruction log: `logs/unwrap-self.log`.
The wrapper refuses to overwrite an existing different ELF. It is not a decryptor, compiler,
native executable, or proof that the port boots. Do not alter ELF type/base just to suppress warnings.

## Audio seed observation

`ffprobe` identifies `sce_sys/snd0.at9` as ATRAC9, 48,000 Hz, stereo, 122.88 seconds.
Existing FFmpeg decoded its first five seconds into 480,000 finite float samples, all nonzero;
peak absolute sample about 0.05827. Record: `local/audio/probe.json`; output stays private.

This establishes one package-menu/splash audio decode without Sony modules. It does NOT
establish gameplay audio-bank formats, NGS2 processing, effects, event routing or live sound.
Those remain AUD-01..04. No actual game audio playback has been claimed.

## Integrity and next steps

Run `python3 scripts/inventory_game.py` after extraction ends; it hashes supplied PKGs,
checks for changes during hashing, reads SFO identities, lists extracted files, and records
PSARC headers and executable/module/sound hashes. This is a container inventory, not a full
archive validator. Run `python3 scripts/test_project_tools.py` for SELF/overwrite/index fixtures.

Keep original inputs, extracted bytes, private evidence, tools and public documentation separate.
Do not include any of them in a source release accidentally. Continue with
[REVERSE_ENGINEERING](REVERSE_ENGINEERING.md), then DATA-02 for format/overlay validation.
