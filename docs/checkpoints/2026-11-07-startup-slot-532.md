## What the body is

832 B at `0x143f50`, table word `0x2dd70e0 - 8*532 = 0x2dd6040`. One straight-line run: `push rbp; mov
rsp,rbp; push r15/r14/rbx; push rax`, then 21 identical groups, then the epilogue. **No local frame, no
stack guard, no conditional branch anywhere.**

Group *i* (object `0x2ee2a58 + 0x20*i`, i = 0..20):

```
lea  rbx, object        ; lea rdx, literal ; xor esi,esi ; mov rdi,rbx
call 0xf2f0             ; SharedStr(ptr, strlen, 0, 0)
mov  rdi,0xf7b0         ; mov rsi,rbx ; mov rdx,0x1604218
call __cxa_atexit       ; group 20 ends in `jmp __cxa_atexit` after the epilogue
```

The views are **borrowed**: 0xf2f0 stores `{ptr, strlen, 0, 0}` and the 0x20-byte object has no control
block, so nothing is allocated and no release call appears. The 21 literals are **interior pointers into
debug strings** (source paths and pretty-function tails); several windows contain non-UTF-8 bytes,
which is expected for an interior pointer.

## Two facts that cost a rebuild each

1. **The literal windows overlap.** Entry 3's window (`0x3f` B at `0xfa8e00`) runs into entry 4 at
   `0xfa8e31`. The first fixture asserted disjoint windows and failed on real data; it now asserts
   ascending order and measured lengths only.
2. **Group 1 starts `0x34` B after group 0, not `0x26`.** Group 0 lacks the three-register prologue.
   `0x26` is the stride from group 1 onward. The first checker used the wrong base and failed at
   `0x143f80`.

A third trap was in the tooling, not the model: `CHECKER532=0` in one run came from `tail` masking the
exit status. The checker must be run unpiped for its status to mean anything.
