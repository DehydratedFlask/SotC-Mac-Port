## Install rows

self-registered (`0x256bae` → `0x8f6f0(obj,&0x2eec4d8)`, `0x256c4c` →
`0x95a90(obj,&0x2eec4e0)`), and one slot row allocates inside its factory (`0x256d01` →
`0xa2b960` → `new(0x178)` + `0xa2afb0` → `this+0x3b48`). So there are **19 slot rows** (18 outside
the already-lifted registry) plus 2 self-registered allocations.

- (b) direct dtor + `0x170b0` — 11 rows, byte-identical to the lifted `owner_dtor_1bdae0` sequence;
- (c) no replace check at all — row 7 (`0x2ed37b8`), a 1-byte object stored unconditionally.

Ctor liftability: `0xa1cc0` is a bare `ret`; `0xfafb0` is a 24-insn vptr + two `memset` + three
pointer fields; `0x26f820` is 16 insns with two hooks (`0x3eba0`, tail `0x3b310`); `0xa2b960` is a

## Gate and mode

The gate is the **`RetailBuild`** boolean:

```
2570a9  lea rbx,[0x2dfce70]
2570b0  mov rax,[rbx+0x60]
2570b4  cmp byte [rax],0
2570b7  jne skip
```

`0x2dfce70` is the singleton that registers `"RetailBuild"` (`0xf96100`) and `"BuildVersion"`
(`0xf9610c`); the same test appears at `0xa2b1a5` and `0xa2b490`. `gate == 0` also triggers
`0x4a910(obj90, **(0x2dfd088+0x60), this+0x2630)` (ToolServerIP, 1 MiB alloc), modelled as a hook.

Mode is `dword [a2b960()+0x10]`. `0xa2b960` is a plain factory with exactly one caller (`0x256d01`),
and `0xa2afb0` writes `dword [obj+0x10] = 1` at `0xa2b143` on every path. Therefore **mode == 1 at
this call site**, and the 120-site mode-2 block `0x257171..0x2584f2` is unreachable from
`0x2569d0`. It stays in the native table as data only.
