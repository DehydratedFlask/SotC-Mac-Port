- **`poiGroup` is 8 bytes, not 7.** The first fixture draft used 7 and failed its own length check;
  the rodata length at `0xfe94ad` is `8`, and `0x20af0` receives 8. Fixed in the header and fixture.
- **The slot oracle's native scan needs full literals.** The 0x82-byte `poi` description was split
  across two C++ literals; the compiler concatenates them but the source scan saw neither half as
  the full string. Joined into one literal.
- **The slot checker listed a private callee name.** `"concmd_functor_6af60"` in `SPEC["callees"]`
  raised `KeyError` because `l4_slot_lib.COMMON_CALLEES` only knows shared helpers. Removed; the
  pair has its own oracle, so no coverage was lost.
- **The new first gap is 468, not 463.** 463 (`0x3e0040`) was already registered before this batch;
  with 462 now registered, the first unregistered index is **468 / `0x3c3a90`**. The coverage test,
  `check_ctor_slots.py` and `check_console_var_ctors.py` were corrected together.
- **`startup_ctors` pins an explicit slot list.** The recovered set is not a prefix; 462 had to be
  inserted between 461 and 463 in `test_startup_ctors.cpp`'s `expect[]`, otherwise the size assertion
  failed even though the row was registered.
- **`source_order` is source order, not call order.** `init_debug_menu_item_26ea0` is defined before
  `init_slot462_3e2730`, so it appears before `init_concmd_functor_6af60` in the `.cpp`; the checker
  now lists the real first-occurrence order.
- **The menu-root first-use row is not this slot's.** The fixture pre-initialises the root so the
  first-use `0x27280` atexit record is not attributed to 462; in production earlier slots have
  already created the root. The slot's own four rows are `0x272d0`.
- **The generated survey left a trailing space** when the pure-slot set was empty
  (`- pure: 0 slots: `), which `git diff --check` flagged. The generator now `rstrip()`s that line and
  the regenerated survey is clean.
