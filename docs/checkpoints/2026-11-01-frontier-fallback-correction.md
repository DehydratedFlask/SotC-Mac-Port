## Premise

The bounded store-to-load pass (`tools/lift/store_to_load_forwarding.py`) found nine rows whose call
site reads `TABLE + 0x10 + slot`, not the recorded `TABLE + slot`. **It reproduces.** Every site is
`movq (%X),%rax; call *disp(%rax)` and the store of `(%X)` is `lea TABLE(%rip); add $0x10` (or
`lea 0x10(%A)`), the Itanium address point. A fallback tie records the older `lea` plus the
displacement, which is not the address the call reads.

## Hand argument (NOT machine-checked)

That `(%X)` still holds `TABLE + 0x10` when the call executes needs: (a) callees between the store
and the call never write object offset 0 (argued by reading each callee's write set during the audit;
not re-verified by any tool); (b) virtual calls in between resolve through the same vptr and are covered by
the same argument; (c) PLT imports in between (`sceFiosOpWait`) take a scalar `edi` handle; (d) the
object is freshly allocated and there is no branch entering the region from outside the function. The
checker proves the shape and the image facts; it does not prove (a)-(d), which is why grades did not move.
