value stored is still the result of call *i*, and the store order is exactly `i = 0..39`. Decoded from

## The converter `0x157e90` (203 B), read instruction by instruction

`e = (bits >> 23) & 0xff`, `mant = bits & 0x7fffff`, `sign = (bits >> 16) & 0x8000`, `ecx = e - 0x70`.

| path | condition | behaviour |
|---|---|---|
| subnormal / zero | `ecx <= 0` | `ecx < -0xa` returns the sign alone (flush to a **signed zero**); otherwise the implicit bit is restored and `(m + (1 << (0x7d-e)) - 1 + ((m >> (0x7e-e)) & 1)) >> (0x7e-e)` rounds **half to even** at subnormal spacing. Reachable shifts are 14..24, so `cl & 31` masking never engages. |
| inf / NaN | `e == 0xff` | `mant == 0` → `sign | 0x7c00`; else `sign | 0x7c00 | (mant >> 13) | (1 if payload == 0)`, a NaN payload formula, never plain inf. |
| normal | otherwise | `d = mant + bit13 + 0xfff` (round half to even, `bit13 = (bits >> 13) & 1`). Carry into bit 23 → exponent `e - 0x6f` and the payload is **dropped**; no carry → exponent `e - 0x70` and payload `d >> 13`. `exp >= 0x1f` saturates to `0x7c00`. |

## Correction of the previous triage note

The earlier note in `HANDOFF.md` said the normal path **truncates** and that 65520.0f returns 65504.
Both claims were wrong and are withdrawn:

- The `+0xfff + bit13` term is round-half-to-even, not truncation (the `shrl $0xd` only extracts the
  already-rounded field).
- 65520.0f is `0x477ff000`, whose bit 13 **is set**, so `mant + bit13 + 0xfff` carries into bit 23 and
  the result saturates to `0x7c00`. `0x477fe000` (65504.0) is the largest finite result, `0x7bff`.
- The `cmp $0x8f` is against `e - 0x70`, i.e. `e == 0xff`, not `e == 143`. The `0x1f` compare in the
  normal path is the saturation test.
