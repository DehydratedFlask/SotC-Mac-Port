## Result

`0x210b0` is the ConCmd manager constructor plus the queue drain. Pinned ELF `d0723afb…61d3`
(re-hashed this session), image base 0, RVA == address. Body `0x210b0..0x211c1` = **273 B**,
sha256 `619fba45…17ff40`, FDE `(0x210b0, 273)`; 4 branches, 4 relative calls to 4 distinct targets,
no `e9`, no indirect transfer.

| Phase | Bytes | What it does |
|---|---|---|
| header stores | `0x210c9..0x210ea` | `+0x08 = +0x10 = this+8`, `+0x18 = 0`, 16 zero bytes at `+0x20`, one more zero byte at `+0x20`, 16 zero bytes at `+0x38`, `+0x48 = 0`. `+0x00..+0x07`, `+0x30..+0x37`, `+0x50..+0x57` are **not** written. |
| CritSec | `0x210f2` | `0x3b310(this+0x58)`; the return code is discarded. |
| guarded static list | `0x210f7..0x21135` | the same 63-byte `0x2dfce50`/`0x2dfce60` construct as `0x20e7f` (register) and `0x2171b` (lookup): byte-identical once the seven RIP displacements are masked. |
| drain | `0x21136..0x2117d` | `link = [0x2dfce50]`, `element = link - 8`, sentinel `0x2dfce48`; per element `0x20d80(element, manager)` then `element = [element+0x08] - 8`. FIFO, oldest first. |
| re-termination | `0x2117f..0x211af` | re-read `[0x2dfce50]`, `first = link-8`, `prev_link = [first+0x10]`, `tail = prev_link-8`, `[tail+0x08] = &head`, `[0x2dfce58] = prev_link`. |

Three findings that decide the model:

1. **The drain calls `0x20d80`, never `0x20d60`.** `0x20d60` sets `+0x18 = 1` and tail-jumps to
   `0x20d80`, so every queued command already has `registered == 1`; a drain through the guard entry
   would return at `cmpb [rdi+0x18],0` and insert nothing.
2. **The manager is the body's argument, not `[0x2dfcbc8]`.** `0x20d80` branches on
   `testq %r13,%r13` (its second argument), and the installer stores the cell only *after* the
   constructor returns: `0x243a1 new(0x60)` → `0x243b1 call 0x210b0` → `0x243f5 mov %r14,(%r15)` on the
   `0x2dfcbc8` `lea` at `0x243b6`. During a real drain the cell is still null.
3. **The tail block re-empties the head without unlinking the nodes.** `0x20d80`'s pending path
   writes `cmd->prev = old head.prev` and `head.prev = &cmd->pending`, so for a list it built the
   first element's `prev` is the head *link* `0x2dfce50`; `0x21198` therefore yields the sentinel and
   the two stores land on `head.next` and `head.prev` themselves. The nodes keep their links.
   A list whose first element's `prev` points at the last node only re-terminates and is *not*
   emptied — the model implements the general form, and the fixture pins both outcomes.
